# Правила проекта

> Короткие, практические правила и соглашения для Wct.by. Автоматически загружаются `/aif-implement`.

## Правила

- Весь пользовательский ввод должен проходить валидацию через FormRequest или `$request->validate()` перед передачей в сервисы
- HTML-контент (описания товаров, категорий) должен очищаться через `HtmlSanitizer` перед сохранением в БД
- Массовое присвоение (mass assignment) разрешено только через `$fillable` — не использовать `$guarded = []`
- Пароли, API-ключи и токены никогда не должны попадать в логи (`storage/logs/laravel.log`)
- Загружаемые файлы должны проверять MIME-тип на серверной стороне через валидацию Laravel (`mimes:...` или `mimetypes:...`)
- Ошибки с конфиденциальными данными (email, адрес) не должны возвращаться в ответах API — логировать внутренне, отдавать общее сообщение пользователю
- Все POST/PUT/DELETE-маршруты должны быть защищены CSRF-токеном (стандартно в Laravel, не отключать через `$except`)
- Чувствительные операции (оформление заказа, изменение email/пароля) должны требовать повторную аутентификацию через `password.confirm`
- Запросы к внешним API (платёжные шлюзы, соцсети) должны иметь таймаут и обработку ошибок соединения
